# 260815 — anchor-cluster coherent mixer (the p-knob) · build & verification report

**Built and verified 2026-08-15. Not launched — no experiment config exists yet; p_max
and the run matrix are a separate decision after this report is read.** All four hard
gates pass; measurements M1–M5 below are the numbers that decision needs.

Verification: `scripts/verify_coherent_sampler.py`, 16 cells × 200,000 plan draws

## 1. What this build is

exp002.2 (fully coherent, p=1.0) collapsed, and its result was **uninterpretable by
construction**: drawing the song first made density and class identity follow real 편성 —
realised density fell 5.00 → 3.24 and per-class exposure collapsed (양금 to 0.10×, 기타
to 0.20×). Coherence and exposure moved together, so nothing about the collapse could be
attributed to coherence itself.

This sampler unlinks them. **Density and class identity are decided FIRST, uniformly;
only then does the sampler decide which members of that class set are mutually
coherent.** Exposure is uniform by construction at every value of p — that is gate G1,
and it holds:

1. `n ~ U[density_uniform_min, 9]` — density
2. `S` = n classes, uniform without replacement — **exposure fixed here, before p exists**
3. `k = ⌊p·n⌋ + Bernoulli(frac(p·n))`, so `E[k] = p·n`; a degenerate k=1 (one stem is
   coherent with nothing) snaps to 0 or 2 by fair coin, preserving `E[k]`
4. fill loop: anchor songs drawn per `anchor_selection`; each contributes one
   **cluster** — the classes of S it makes jointly audible at ONE shared offset, capped
   by remaining need. Shortfall is accepted and logged, **never repaired by resampling
   S** — that would leak the exposure bias back in
5. everything unclustered → ordinary incoherent draws (independent songs and offsets)

Coherence holds *within* a cluster; between clusters it is ordinary incoherent mixing.

## 2. What was implemented

`src/data/mix_dataset.py` — the sampler above, replacing exp002.2's song-first coherent
path. Every item is now **planned before any audio is read** (`_plan_item` = all RNG,
`__getitem__` = realisation), which is what lets 3.2 M verification draws run through
the real sampling code.

**New config keys** (all default-compatible — existing configs behave identically):

| key | default | meaning |
|---|---|---|
| `gugak_mix.coherent_mix_prob` | 0.0 | p. **Read per draw, never cached** — the curriculum seam. E[coherent stems] = p·n |
| `gugak_mix.anchor_selection` | `uniform` | `greedy` = single anchor, max overlap, accept shortfall (Method A) · `uniform` = uniform over eligible anchors, loop until filled (Method B) · `overlap_weighted` = P ∝ \|overlap\| (interpolation) |
| `gugak_mix.density_uniform_min` | 1 | lower end of the uniform n draw. 1 preserves exp002 exactly; new runs will set 2 (prof 2026-08-10). Default untouched |
| `gugak_mix.cluster_shared_channel_swap` | true | ONE L/R swap per cluster (the exp002.2 per-mix-swap behaviour, now with the config field it lacked); incoherent stems stay per-stem |
| `gugak_mix.cluster_shared_gain` | false | wired but **off** — ⚠️ open design decision, §6 |

**Mechanics worth knowing** (details that make the guarantees real):

- **Anchor eligibility is precomputed, not rejection-sampled.** For every song and
  class pair, the two classes' active segments are intersected **at file level** and
  contiguous joint spans > 2.51 s kept (coverage threshold 0.25 × 10 s window + 10 ms
  rounding margin). A cluster window is then placed to *contain* its chosen joint span
  (or sit inside it when the span is longer than 10 s) — so ≥ 2 members clearing the
  audibility bar is guaranteed by geometry, with zero retries. File level matters
  because 타악기 is several instruments in separate files: a class-level union could
  promise joint activity no single drawable file sustains.
- "Audible" is the project's one definition throughout — activity covering > 25% of the
  window, the same test `chunk_activities` uses.
- The r=1 exit rule: a leftover need of one either **grows the last cluster** by one
  class that was already audible in that cluster's own window (inheriting its shared
  swap/gain), or drops to incoherent.
- The anchor pool (song regroup + pairwise joint-span index) builds lazily on first
  coherent draw, so a p=0 run pays nothing — but a curriculum ramping p up from 0
  mid-training works without a restart.

## 4. Measurements — the numbers that pick p_max

### M1 · H, the real treatment variable

H = Σᵢ C(kᵢ,2) / C(n,2): the fraction of instrument *pairs* in a mix that are true
unison. p is only what we configure; **H is the dose the model actually receives.**
(→ `fig_m1_h_mean.png`, per-(p, n) grid; `metrics/h_stats.parquet` has p10/p50/p90.)

Mean H over all mixes with n ≥ 2:

| mode | p=0 | 0.25 | 0.5 | 0.75 | 1.0 | P(H=1) at p=1 |
|---|---|---|---|---|---|---|
| uniform | 0 | 0.085 | 0.228 | 0.456 | **0.617** | 0.274 |
| overlap_weighted | 0 | 0.086 | 0.238 | 0.485 | **0.661** | 0.306 |
| greedy | 0 | 0.086 | 0.245 | 0.540 | **0.909** | **0.789** |

What this says:

- **H grows super-linearly in p** (pairs ≈ k², so H ≈ p² territory): p=0.5 delivers
  only ~0.23 of pairs in unison, p=0.25 a mere ~0.085. A mid-p run is a much gentler
  dose than the p-value suggests — worth remembering when choosing sweep points.
- **Below p≈0.75 the three modes are nearly identical.** The mode choice only matters
  at high p, where it spans a *wide* range: at p=1.0, greedy delivers exp002.2-like
  full-ensemble unison (79% of multi-stem mixes fully coherent), uniform delivers a
  many-small-clusters texture (H 0.62, only 27% fully coherent) — same declared p, very
  different musical treatment. p and mode are genuinely two axes.

### M2 · cluster sizes at p=1.0 (→ `fig_m2_cluster_sizes.png`)

| mode | size-2 share | size distribution character |
|---|---|---|
| uniform | 48% | steeply decaying — many duets, few big clusters (8–9 nearly absent: 1.4%) |
| overlap_weighted | 43% | same shape, slightly fatter tail |
| greedy | 14% | **near-flat 2→9** — one anchor swallows whatever n asked for |

Genre share of clusters at p=1: greedy concentrates 55% of all clusters in 창작국악
(the big-편성 genre; 풍류음악 25%) and drives 산조 to 0.1%; uniform keeps 산조 at 6.5%
and 판소리 at 28%.

### M3 · does 산조 survive in the anchor pool at high k? (→ `fig_m3_anchor_genres.png`)

산조 share of realised anchors, by declared k, at p=1:

| mode | k=2 | k=5 | k=9 | verdict |
|---|---|---|---|---|
| uniform | 0.9% | 5.1% | **10.3%** | ✅ survives — share *rises* with k, because high k means several clusters and 산조 (2–3 classes) keeps anchoring the small later ones |
| overlap_weighted | 0.9% | 2.9% | 4.1% | 🟡 marginal — present but suppressed |
| greedy | 0.9% | 0 | 0 | ❌ excluded beyond k=2 — max-overlap never picks a 2–3-class song while big-편성 songs exist |

The corollary for exp002.2's post-mortem: its worst failure cells were 산조 plucked
strings. Under greedy at high p, 산조 essentially never anchors — its stems appear
mostly *incoherently*. Under uniform, 산조's real 병주/장단 pairings stay in the
coherent diet. If the 산조-unison hypothesis matters to the experiment, greedy is the
wrong mode at high p.

### M4 · shortfall (→ `fig_m4_shortfall.png`)

Overall realised vs declared E[k], and the shortfall rate (draws ending short):

| mode | p=0.25 | p=0.5 | p=0.75 | p=1.0 | E[k] real/target at p=1 |
|---|---|---|---|---|---|
| uniform | 0.7% | 4.8% | 14.3% | 33.5% | 4.56 / 5.005 = **0.911** |
| overlap_weighted | 0.3% | 2.6% | 12.2% | 33.0% | 4.57 / 5.005 = 0.912 |
| greedy | 0.0% | 0.4% | 3.5% | 18.8% | 4.61 / 5.005 = 0.921 |

- **`no_eligible_anchor` fired 0 times in 2.4 M coherent-engaged draws** — the 676-song
  pool always offers an anchor for any class pair. Every bit of shortfall is the r=1
  drop rule (uniform p=1: 33.5%) plus greedy's deliberate single-anchor stop (5.9% at
  p=1). Each dropped stem is exactly one stem demoted to incoherent.
- Net effect: the p knob's *realised* ceiling is ≈ 0.91 — configuring p=1.0 delivers
  E[k]/n ≈ 0.91, not 1.0. The n=1 mixes (11% of draws at n_min=1) contribute most of
  this; **at the go-forward `density_uniform_min: 2` the gap will shrink.**
- Also quantified: k=1-snap can clamp at n=1 (k forced to 0); those 12 (p, n=1) cells
  are excluded from strict tracking by design and carry their declared loss of p.

### M5 · draw-time cost

- **Plan path**: 93–94 µs/mix at p=0 → 109–143 µs at p>0 (worst: overlap_weighted).
  A +50 µs ceiling per mix is noise against an ~88-min training epoch.
- **Full audio path** (DataLoader, 10 workers): p=0 baseline 1.6 items/s; every p>0
  cell *faster* (2.1–2.9 items/s) — cluster members read the same file region, so page
  cache locality improves. **Coherent mixing costs nothing at train time.**

## 5. Interpretive summary for the p_max decision

Not a recommendation — the numbers arranged for the meeting:

- The treatment dose is H, and H(p) is convex: {0.25, 0.5, 0.75, 1.0} in p is roughly
  {0.09, 0.23, 0.47, 0.62–0.91} in H. Equal-H spacing would push sweep points higher.
- Mode is a second axis that only opens up at high p: uniform = many small real
  pairings (산조 included), greedy = exp002.2-like full ensembles (산조 excluded).
- Exposure is flat everywhere, so whatever a p-sweep shows is attributable to
  coherence, not diet composition — the confound exp002.2 died of is closed.

## 6. Open design decisions (flagged, not decided)

- **`cluster_shared_gain`** — currently `false`: the per-stem random gain (0.25–1.25)
  is applied independently *inside* a cluster, which augments balance but destroys the
  anchor's real inter-instrument balance — arguably part of what "real ensemble" means,
  and loudness-balance realism is information a separator can exploit. The knob is
  wired (`true` = one gain per cluster, members inherit) but **behaviour unchanged in
  this build** per spec. Needs a decision before any run that claims to train on "real
  ensembles".
- **피리1/2/3 (multi-file classes) inside a cluster** — current behaviour, unchanged
  from exp002.2: a class contributes **one file, drawn uniformly among those clearing
  the audibility bar** — never their sum (`draw_unit: file`). So a cluster from a
  2-피리 song carries one 피리 against the full ensemble. This is not rare: 380 of
  3,826 (9.9%) train (song, class) cells hold >1 file — 타악기 dominates (131 cells, up
  to 5 files), so a clustered 타악기 stem is often one drum of several that played
  together. The summed alternative is the reserved `draw_unit: song_base` seam.
- **Greedy's overlap is measured against all of R, not min(overlap, r)** — a k=2 greedy
  draw still picks the biggest-편성 eligible song, then thins to 2 members uniformly.
  Defensible reading of "maximum overlap with R", but it is *why* greedy's genre
  concentration appears even at low k.

## 7. Things the spec didn't anticipate

- **Greedy = literally one anchor.** "Single anchor … accept shortfall" conflicts
  mildly with "same loop under different anchor selection rules": a greedy loop that
  kept iterating would be multi-anchor. Implemented as: the fill loop breaks after
  greedy's first anchor (`greedy_single_anchor` logged when r ≥ 2 remains). The r=1
  grow rule still applies to that single cluster.
- **The k=1 snap can re-collide with the n-clamp at n=1** (snap → 2, clamp → 1 →
  degenerate again). Resolved: k < 2 after clamping becomes 0; only n=1 is affected;
  counted and reported (G3's clamped cells).
- **`plan_item` changed shape** (returns the full `MixPlan`, never `None`), so
  `scripts/render_coherence_examples.py` — which consumed the old `CoherentPlan` — is
  **stale**: its `_draw_excerpt`/`_augment_stem` helpers were kept alive, but its
  plan-scanning entry point needs a rework to render cluster examples. Deferred; the
  script was exp002.2 listening material, not training infrastructure.
- The old verifier's exp002.2-specific characterisation (co-occurrence ratios,
  effective-content estimate) described the song-first draw and was **removed**; H (M1)
  is its successor as the unison-dose statistic.
- Exposure across grid cells is *identical*, not merely similar (see §3) — a stronger
  property than G1 asked for, worth knowing when reading the parquet.
- Audio throughput *improves* with p (M5) — anticipated as a cost, measured as a gain.

# DELTA — melodic-pair requirement (2026-08-15, same-day follow-on)

**Change: a cluster is valid only if it contains ≥ 2 NON-PERCUSSION classes.** 타악기
may join a cluster, but never counts toward the minimum and can never be the reason a
cluster exists — a {타악기, one melody} cluster is a drum over a single line, timbrally
orthogonal, inflating k and H while teaching nothing about heterophonic unison. This is
a claim about musical structure, not genre; no genre is excluded anywhere.

The numbers below supersede §4 where they differ. Everything not listed here is
unchanged. `metrics/*.parquet` and `figures/` now hold the post-rule state; the
before-numbers survive in §4's text and in this section's tables.

## What changed in code

- `gugak_mix.cluster_min_melodic` (int, default 2) + `gugak_mix.stem_taxonomy` (path
  key, default `configs/stem_taxonomy.yaml`). **Percussion-ness is resolved from the
  taxonomy's per-instrument `pitched` field** — a class is melodic iff it holds ≥ 1
  pitched instrument — never from names. Under this 9-class scheme only 타악기 (all
  `pitched: false`) resolves percussion; an 11-class scheme's pitched_percussion
  (편종·편경·방향, tuned idiophones) resolves melodic, as it should.
- Anchor eligibility filters the precomputed joint-span index to **valid seed pairs**
  (pairs carrying ≥ `cluster_min_melodic` melodic classes) at query time — still fully
  precomputed, no rejection sampling. Eligibility can now be genuinely empty (e.g.
  R = {타악기, one melody}), which logs `no_eligible_anchor` and demotes to incoherent.
- Member thinning (`_thin_members`) draws the required melodic members first, the rest
  uniformly — never dropping below the minimum. Two consequences: 타악기 only ever
  joins clusters of ≥ 3, and thinned member sets are *slightly* melodic-favoured
  relative to uniform-over-valid-subsets (each subset weighted by how many ways its
  melodic part could be the required draw) — a documented, rule-conservative bias.
- Values > 2 raise NotImplementedError: pairwise spans can guarantee at most 2 jointly
  audible melodic classes; ≥ 3 would need a triple-wise index (reserved).

## D4 · 산조 — fell to exactly zero, and structurally so ⚠️

Intended direction, total in magnitude: 산조 anchor share (uniform, p=1.0) went
0.9%/5.1%/10.3% at k=2/5/9 → **0 everywhere; overall cluster share 6.5% → 0.000**.
The spec expected "near-zero, keeping only 병주-type passages" — but the manifest says
**all 150 산조 train songs carry exactly one melodic class** (the solo instrument;
everything else is 장구). There are no 병주-type 산조 songs in the train pool, so no
산조 song can ever seed a melodic pair. Consequence worth stating plainly: under this
rule the coherent path delivers **zero 산조 passages at any p** — 산조 stems reach the
model only through incoherent draws. Since exp002.2's worst cells were 산조 plucked
strings, any future claim about coherence helping 산조 must account for 산조 never
being *in* the coherent diet. (This is the rule's own logic — those passages are
solo-plus-percussion, not heterophony — but it is now a fact of the training
distribution, not a tail.)
